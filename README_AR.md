# نظام إدارة صيانة ماكينات الخياطة — Realtime Database وبدون تسجيل دخول

## الملفات
- `index.html`: واجهة النظام.
- `style.css`: التصميم.
- `firebase.js`: إعدادات مشروع Firebase الحالي `sstmy-627dc`، ومحدد فيه عنوان Realtime Database الظاهر في صورك.
- `app.js`: كود الماكينات وسجل الصيانة وقطع الغيار، يستخدم Realtime Database وليس Cloud Firestore.
- `database.rules.json`: قواعد Realtime Database لهذا الإصدار.

## التشغيل
1. ارفع محتويات مجلد `sewing_maintenance_system` إلى GitHub Pages أو استضافة تدعم HTTPS.
2. افتح Firebase Console واختر المشروع `sstmy-627dc`.
3. ادخل Build → Realtime Database → Rules.
4. استبدل القواعد بقواعد الملف `database.rules.json` ثم اضغط Publish.
5. افتح الموقع من جديد، ثم أضف ماكينة تجريبية. ينبغي أن تظهر في تبويب Data تحت `machines`. وتظهر عمليات الصيانة تحت `maintenance`.

## مهم جدًا بشأن الأمان
القواعد في هذه النسخة تسمح بالقراءة والكتابة لأي زائر على المسارين `machines` و`maintenance` لأنك طلبت إزالة تسجيل الدخول. هذا غير آمن للاستخدام الحقيقي؛ أي شخص يمكنه تعديل أو حذف البيانات. استخدمها للاختبار فقط، والحل الآمن هو تفعيل تسجيل الدخول أو إنشاء خادم يتحقق من الصلاحيات.

## ملاحظات
- هذه النسخة تستخدم **Realtime Database** وعنوانها `https://sstmy-627dc-default-rtdb.firebaseio.com`.
- لا تحتاج إلى إعداد Firestore أو نشر قواعد Firestore لهذه النسخة.
- لو ظهر خطأ، افتح Console في المتصفح أو أرسل صورة الرسالة الظاهرة داخل الموقع.


## إصلاح الحفظ (نسخة أكتوبر 2026)
- عند الضغط على حفظ الماكينة يظهر تنبيه إذا كان السيريال أو نوع الماكينة ناقصًا.
- يظهر مؤشر «جارٍ الحفظ» ثم رسالة نجاح أو رسالة خطأ واضحة.
- بعد الحفظ يتحقق التطبيق من وجود السجل داخل `machines/<id>`.
- إذا لم يعمل الزر بعد رفع هذه النسخة، ارفع جميع الملفات معًا إلى GitHub Pages ثم افتح الموقع في نافذة خاصة/حدّث الصفحة تحديثًا كاملًا.
- تأكد أن `firebase.js` يستخدم عنوان Realtime Database الصحيح وأن قواعد قاعدة البيانات تسمح بالكتابة أثناء الاختبار فقط. لا تترك قواعد الكتابة العامة في الاستخدام الفعلي.
