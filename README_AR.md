# نظام إدارة صيانة ماكينات الخياطة — ربطه بمشروع Firebase موجود

هذا المشروع يستخدم **Firebase Authentication + Cloud Firestore**. يمكنك ربطه بمشروع Firebase الحالي دون إنشاء مشروع جديد، بشرط أن تكون قاعدة البيانات المستخدمة هي Cloud Firestore. إذا كانت قاعدة مشروعك من نوع Realtime Database، فهذا الكود لن يعمل معها مباشرة لأن واجهات الاستعلام والقواعد مختلفة.

## 1) خذ إعدادات تطبيق الويب من مشروعك الحالي
1. افتح https://console.firebase.google.com/ واختر مشروعك الحالي.
2. اضغط ⚙️ Project settings ثم General.
3. من قسم Your apps اختر تطبيق الويب الموجود، أو أضف Web app داخل **نفس المشروع** إذا لم يكن لديك تطبيق ويب. إضافة Web app لا تنشئ مشروع Firebase جديدًا.
4. انسخ كائن `firebaseConfig` الذي يظهر لك.
5. افتح `firebase.js` واستبدل القيم `YOUR_...` بالقيم التي نسختها. اترك أسماء المفاتيح كما هي.

مثال توضيحي فقط — لا تستخدم القيم التجريبية كما هي:
```js
const firebaseConfig = {
  apiKey: "ضع_apiKey_من_مشروعك",
  authDomain: "اسم-مشروعك.firebaseapp.com",
  projectId: "اسم-مشروعك",
  storageBucket: "القيمة_التي_يعرضها_Firebase",
  messagingSenderId: "القيمة_التي_يعرضها_Firebase",
  appId: "القيمة_التي_يعرضها_Firebase"
};
```

## 2) تأكد من نوع قاعدة البيانات
من القائمة الجانبية في Firebase Console:
- إذا وجدت **Firestore Database**، أكمل الخطوات أدناه.
- إذا كانت بياناتك في **Realtime Database** فقط، لا تلصق إعداداتها في هذا المشروع وتفترض أنه سيعمل؛ أرسل نوع قاعدة البيانات أولًا ليتم تجهيز نسخة Realtime Database المناسبة.

## 3) تفعيل تسجيل الدخول
1. افتح Authentication → Sign-in method.
2. فعّل Email/Password.
3. من Authentication → Users أضف حساب المدير إذا لم يكن موجودًا.
4. انسخ UID الخاص به.

## 4) تجهيز Firestore
1. افتح Firestore Database في المشروع الحالي.
2. إذا كانت قاعدة Firestore موجودة بالفعل، لا تنشئ قاعدة ثانية. استخدم قاعدة البيانات الموجودة.
3. افتح تبويب Rules، وراجع قواعدك الحالية قبل تعديلها. الملف `firestore.rules` في هذا المشروع مثال لقواعد المجموعات التي يحتاجها التطبيق؛ نشره كما هو قد يستبدل قواعد موجودة ويؤثر في تطبيقات أخرى تستخدم نفس قاعدة البيانات. خذ نسخة من قواعدك الحالية أولًا وادمج القواعد بحذر.
4. يحتاج الموقع المجموعات التالية: `users`, `machines`, `maintenance`.
5. في مجموعة `users` أنشئ مستندًا معرّفه هو UID المدير نفسه، وأضف الحقول:
   - `email` نوع String
   - `name` نوع String
   - `role` نوع String وقيمته `admin`

إذا كانت مجموعة `users` مستخدمة بالفعل في تطبيق آخر، افحص بنيتها قبل إضافة المستندات أو تغيير القواعد.

## 5) إضافة بقية المستخدمين
1. أنشئ حساب كل مستخدم من Authentication → Users → Add user.
2. انسخ UID الخاص به.
3. أنشئ مستندًا داخل `users` ومعرّفه UID نفسه، ثم أضف `email`, `name`, `role`.
4. الأدوار: `admin` مدير، `supervisor` مشرف، `technician` فني، `viewer` مشاهدة فقط.
5. لا تضع كلمات مرور المستخدمين داخل ملفات الموقع. لا تستخدم مفاتيح Admin SDK أو Service Account في المتصفح.

## 6) تشغيل الموقع
- فك الضغط عن ZIP.
- افتح المجلد في VS Code واستخدم Live Server أو أي خادم محلي.
- لا تفتح `index.html` مباشرة من مدير الملفات.
- للنشر، استخدم استضافتك المعتادة وأضف نطاق الموقع إلى Authentication → Settings → Authorized domains عند الحاجة.

## تنبيه أمان مهم
هذا المشروع يتصل بقاعدة Firebase التي تحددها في `firebase.js`. إعدادات تطبيق الويب ليست كلمة مرور، لكن أمان البيانات يعتمد على Authentication وقواعد Firestore الصحيحة. اختبر كل دور بحساب منفصل قبل استخدام النظام في المصنع. لا تنشر قواعد تسمح للجميع بالقراءة والكتابة.
